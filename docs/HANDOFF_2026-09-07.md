## 2. Como rodar em outro ambiente

### 2.1 Dependências
- Node 24 (o harness de teste usa `node:vm`)
- `clasp` 3.4.1 autenticado na conta que é dona do Apps Script

### 2.2 Armadilhas deste ambiente — leia antes de sofrer
Estas foram descobertas na marra e vão te poupar horas:

- **Node só funciona no PowerShell com o PATH explícito:**
  ```
  $env:Path = "C:\Program Files\nodejs;$env:APPDATA\npm;$env:Path"
  ```
- **git só funciona pelo Bash.** No PowerShell dá problema.
- **Here-strings do PowerShell (`@'...'@`) quebram** com o conteúdo deste projeto. Para editar arquivo, escreva um `.cjs` e rode com node, ou use um editor.
- **Os arquivos misturam CRLF e LF.** Qualquer script de edição precisa detectar e preservar o que já estava lá, senão o diff explode.
- **`assert.deepEqual` falha entre realms do `vm`** para arrays vazios. Compare `.length`.
- **Nos testes, os dublês (mocks) vão DEPOIS de carregar os `.gs`** — declaração de função sobrescreve propriedade do contexto.
- **Em produção todos os `.gs` dividem o mesmo escopo; no teste, cada arquivo lista o que carrega.** Se A passa a chamar B, todo teste que carrega A precisa carregar B. Foi a causa de três quebras de suíte hoje.

### 2.3 Comandos
```
npm test          # 17 arquivos, precisa dar exit 0
npm run push      # roda os testes E só então publica no Apps Script
```

## 3. A disciplina do projeto — mantenha

**Todo teste é verificado por mutação.** Quebre o código de produção de propósito, confirme que o teste FALHA, desfaça, confirme que passa. Teste que passa com o código quebrado é teatro e vale menos que nada, porque dá confiança falsa.

Isso já pagou várias vezes hoje. Dois exemplos reais:
- Um teste "passava" com a trava removida porque nunca a ligava antes de chamar.
- Outro casava com a palavra "preliminar" no `title` em vez do rótulo visível — e ninguém decide uma compra passando o mouse por cima.

Nos dois casos **o defeito era do teste**, e só a mutação revelou.
